# <ディレクトリ名>/CLAUDE.md の雛形（任意）

app の中の、決まりが違う層のディレクトリ（例: バックエンドのコード、フロントエンドのコード、テスト）ごとに置く。
Claude Code は、そのディレクトリの中のファイルを読んだときに、この CLAUDE.md を読み込む。だから、その層を触るときにだけ、その層の決まりが文脈に入る。

**中身は「どの設計書の、どの節を読むか」の指し先だけにする。** 規約の本文や要約は書かない。
書くと、設計書を直したときに 2 か所になってずれ、要約だけ読んで設計書を読まずに済ませる道ができる。

`.claude/project.md` の「置き場」の「設計書」にも、同じ設計書を書いておく。
spec や plan は、コードを読む前（このディレクトリの CLAUDE.md が読み込まれる前）に設計を考えるため。

`<…>` を埋めて、下の線から下だけをディレクトリに置く。

# <層の名前>の規約（指し先）

この配下のコードを変更する前に、必ず以下を読み、従うこと:

- `docs/design/<層>-architecture.md` — <その設計書で、この層を触るときに特に読む節。例 ディレクトリ・主要な型・禁止事項（§4-2）>
- `docs/design/<層A>-<層B>-contract.md` — <境界の契約で決めていること。例 共有するデータの形・失敗の返し方・生成物。無ければこの行を消す>
- テストを書くなら `docs/design/test-strategy.md` §0・§<この層の節>（<テストの置き場。例 テストはこの配下に置く>）

規約と、実装のタスク（spec・plan・指示）が矛盾する場合は、勝手に判断せず報告すること。
